## Least tuned, with next steps

Ranked by how little of items 2 and 3 has been done, weighted by cost in the b6eb311 run. Every step below uses a documented option and leaves the scheme unchanged.

1. **JAX-FEM (both).** Nothing in item 3 has been measured, and it is the slowest mesh solver: structural forward 13.1 s at nx = 128 (Firedrake 1.76 s), thermal VJP 149 s at nx = 1024 (Firedrake 16.3 s).
   - A/B the library default `jax_solver` (BiCGSTAB + Jacobi) against the current host solve.
   - Try `petsc_solver` with CG and an AMG `pc_type`. petsc4py is already in the image; whether hypre is built in is unknown.
   - Then check whether the chosen solver lets the JVP/VJP run under jit again (#81).
2. **deal.II heat.** Untouched since the initial commit. Forward 61.7 s at nx = 1024 against Firedrake's 8.46 s, both on CPU.
   - Measure the 1e-12 CG tolerance against the forward checks and loosen it to the loosest value that leaves them unchanged.
   - Compare SSOR with AMG (deal.II tutorials step-31/40; needs Trilinos or PETSc in the image, unchecked) or with UMFPACK, which the structural binary already uses.
   - Choose one threading policy for both deal.II binaries and measure it.
3. **INS.jl.** Item 3 stops at precision. 3D VJP takes 53.9 s at N = 64 against 9.4 s for PhiFlow.
   - Set `JULIA_NUM_THREADS`. INS.jl's KernelAbstractions CPU kernels can probably use threads.
   - Try INS.jl's documented CUDA backend. Whether Zygote works through it is unknown.
   - Measure whether `JULIA_CPU_TARGET=generic` slows the precompiled code.
4. **OpenFOAM (periodic box).** The channel got GAMG and MPI; the periodic case did not, and its cost is filed as an explained anomaly. Forward takes 35.6 s at N = 256.
   - Use GAMG for p, as the channel does.
   - Use the existing scotch decomposition on the periodic case.
   - Record measurements for the #239 channel settings (item 2 evidence).
5. **PICT (periodic).** Tuning went into the channel only, and `drag_opt` is still excluded as too slow.
   - Measure the default pressure tolerance against the accuracy checks.
   - Try `pressure_use_BiCG` with `preconditionBiCG`. These are constructor arguments; I did not find them documented outside the source, so they may count as L1.
   - Not proposed: more PISO correctors. They would remove the splitting floor, which #232 keeps as an artefact of the method.
6. **PhiFlow (2D).** Measure the CPU against the GPU for 2D (#233 found the GPU about 3x slower). phiml's `Solve(preconditioner="ilu")` exists, but phiml 1.16.1 falls back to a host SciPy solve for ILU on sparse matrices under jit, so the gain on the GPU is uncertain.

Also untuned, but with less to gain: TopOpt.jl (already second fastest in structural) and torch-fem's 1e-10 CG tolerance.

## Decisions (2026-10-28)

- **Device placement.** Moving INS.jl to its library's documented GPU backend is tuning of the same entry (one entry per solver, as for XLB). It then joins the GPU group. If Zygote cannot differentiate through that backend, INS.jl stays on the CPU and records why.
- **XLB's harness time step.** Dropped in favor of the tesseract's own sub-steps (#284).
- **Accuracy need.** The loosest tolerance at which every check of the setup, gradient checks included, is unchanged. Loosening an over-tight tolerance is in scope, as is tightening a loose one: deal.II heat (#266), PICT (#287), torch-fem next.
- **XLA autotuning.** Restore the framework default in jax-cfd, PhiFlow and XLB. The recorded reason (a V100 failure) no longer applies to the benchmark hardware; if a failure reproduces on a T4 or an A100, the flag returns for that solver with the reason recorded.
- **OpenFOAM's periodic cost.** Linear solver and decomposition are tuning, picked by measurement at the benchmark sizes (#269 found the channel faster in serial). Separately, cost checks now compare solvers within their device class, as the results pages do, so a serial CPU solver is no longer flagged for being slower than GPU solvers, and its explained anomaly goes away.
- **phiml pin.** Done (#279).
